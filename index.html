Authentication

All endpoints (except 1.1 Login) require a valid JWT access token in the Authorization header:

Authorization: Bearer <access_token>

1. Authentication

1.1 Login

POST /auth/login/

Broker login with email and password. Returns JWT access and refresh tokens plus broker user details.

Request Body (JSON):

FieldTypeRequiredDescription

passwordstringYesBroker password

Success Response (200 OK):

{
  "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "refresh_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "user": {
    "id": 1,
    "email": "broker@example.com",
    "first_name": "John",
    "last_name": "Doe",
    "is_broker": true,
    "broker_fra_id": "FRA-123"

2. Lead Management

A Lead represents a corporate client. The authenticated broker owns every lead they create. Leads can optionally be nested under a parent lead.

2.1 List Leads

GET /leads/

Returns all leads belonging to the authenticated broker. Use the returned id as parent when creating a child lead or as main_lead_id when creating a quotation.

Headers: Authorization: Bearer <access_token>

    "lead_type": "corporate",
    "company_english_name": "Acme Egypt",
    "company_arabic_name": "اكمي مصر",

    "parent": null,
    "created_at": "2026-09-02T10:00:00Z",
    "updated_at": "2026-09-02T10:00:00Z"
  }
]

3. Quotations

Create Tailored Group Life quotations and define life categories/plans. The product type is always set to group_life.

3.1 Create Quotation

Create a new Group Life quotation. Two scenarios are auto-created: a current scenario (index 0) and a requested scenario (index 1).

Headers: Authorization: Bearer <access_token>

Request Body (JSON):

FieldTypeRequiredDescription

company_arabic_namestringYesCompany name in Arabic
currencystringYesEGP or USD
payment_frequencystringYesmonthly, quarterly, semi_annual or annual
main_lead_idintegerNoLead ID the quotation belongs to (must be owned by broker)
is_virginbooleanNotrue if the company has no prior insurer (default false)
last_insurer_namestringNoPrevious insurer name (relevant when is_virgin=false)

Headers: Authorization: Bearer <access_token>

category_typestringYeslife or sme_life

benefit_idsarray[int]YesList of active benefit IDs; at least one required
is_multiple_of_salarybooleanNoDefault false
ceilingdecimalRequired when is_multiple_of_salary=falseFixed coverage ceiling
FCLdecimalRequired when is_multiple_of_salary=trueFree coverage limit
minimum_sum_insureddecimalRequired when is_multiple_of_salary=trueMinimum sum insured
number_of_monthsintegerRequired when is_multiple_of_salary=trueSalary multiplier months
minimum_membersintegerNoDefault 1
minimum_ageintegerNoMinimum member age
maximum_ageintegerNoMaximum member age

is_activebooleanNoDefault true

Fixed Ceiling Example:

{

  "category_type": "life",
  "quotation_id": 42,
  "rate": "1.500",
  "ceiling": "100000.00",
  "is_multiple_of_salary": false,
  "benefit_ids": [1, 2],
  "minimum_members": 1,
  "maximum_age": 65
}

Multiple of Salary Example:

{
  "name": "Plan B",
  "category_type": "life",

  "FCL": "500000.00",

5. Members

Download the member Excel template, fill it, and upload it back. The template columns and validation logic depend on the quotation's life-plan configuration.

5.1 Download Member Template

GET /quotations/{quotation_id}/members/template/

Download an Excel template for the quotation. This is the same file generated by the admin Download Template button on /admin/smedashboard/premiumcalculation/{quotation_id}/change/.

Headers: Authorization: Bearer <access_token>

Template Columns — Fixed Ceiling:

name | date_of_birth | national_id | dob_from_nid | age_from_nid | country | life_plan | staff_id | member_lead

Template Columns — Multiple of Salary:

name | date_of_birth | national_id | dob_from_nid | age_from_nid | country | life_plan | staff_id | salary | member_lead

Sheet Layout:

  • Members sheet — the sheet to fill and upload
  • Lists sheet — hidden, contains the country dropdown list
  • Reference sheet — lists the allowed life_plan and member_lead values, plus a salary note when applicable

Column Notes:

  • name, date_of_birth, national_id, country, staff_id are stored as text to avoid leading-zero and date-format issues.
  • dob_from_nid and age_from_nid are formula assist columns — they are ignored during upload and are there to help brokers validate the national ID against the date of birth.
  • date_of_birth must be YYYY-MM-DD.
  • salary appears only when is_multiple_of_salary=true for one of the quotation's life categories or group_life_salary_multiple=true.
  • life_plan and member_lead have data-validation dropdowns populated from the quotation's active life categories and the main lead plus its subsidiaries.

Response: Excel file download with Content-Disposition: attachment; filename="members_template_{company_name}_{quotation_id}.xlsx"

5.2 Upload Member Excel

POST /quotations/{quotation_id}/members/upload/

Upload a completed Excel member template. The existing members for the selected scenario are replaced and the quotation premiums are recalculated. This endpoint reuses the existing Tailored member-import validation logic.

Headers:

HeaderValue
AuthorizationBearer <access_token>
Content-Typemultipart/form-data

Request Parameters:

FieldTypeRequiredDescription
excel_filefileYes.xlsx file matching the member template
inception_datedateNoReference date for age calculation (YYYY-MM-DD); defaults to the quotation inception date or today
scenario_idintegerNoScenario to attach members to; defaults to the current scenario

Success Response (201 Created):

{
  "deleted": 0,
  "created": 25,
  "total_members": 25,
  "total_net_premium": "12500.00",
  "total_tax": "0.00",
  "total_with_tax": "12500.00",
  "errors": [],
  "excluded_count": 0
}

Validations:

  • File must be a valid .xlsx workbook; the first worksheet is read
  • Required columns: name, date_of_birth, life_plan
  • Extra columns such as dob_from_nid and age_from_nid are ignored (they are formula helpers from the template)
  • date_of_birth must be parseable as YYYY-MM-DD
  • Life plan value must match an active life category configured for this quotation
  • member_lead value must match the main lead or one of its subsidiaries
  • staff_id is provided in the template but is not imported for Group Life (stored as null)
  • National ID format and duplicate detection (within file and against existing members)
  • Age validation against category age ranges
  • Rows that fail validation are reported in errors and counted in excluded_count

6. Purchase Requests

6.1 Create Purchase Request

POST /purchase-requests/

Convert a Tailored Group Life quotation into a purchase request. The development stamp is forced to 0 and the status is set to pending_client_approval (Pending Client Approval). The KAF policy number and invoices are generated later when an administrator changes the status to pending_issuance.

Headers: Authorization: Bearer <access_token>

Required Field:

FieldTypeDescription
quotation_idintegerID of the Group Life quotation to convert

Optional Fields:

FieldTypeDescription
lead_idintegerLead to associate (defaults to the quotation's main lead)
inception_datedatePolicy inception date YYYY-MM-DD
notesstringFree-text notes
tax_card_numberstringTax card number
commercial_registry_numberstringCommercial registry number
tax_cardfileTax card image/document
commercial_registryfileCommercial registry document

Example Request (JSON):

{
  "quotation_id": 1089,
  "inception_date": "2026-09-01",
  "notes": "Client confirmed via email"
}

Success Response (201 Created):

{
  "id": 42,
  "kaf_policy_number": null,
  "status": "pending_client_approval",
  "quotation_id": 1089,
  "lead_id": 10,
  "inception_date": "2026-09-01",
  "development_stamp": "0.00",
  "created_at": "2026-09-02T10:00:00Z",
  "message": "Purchase request created successfully"
}

Behavior:

  • KAF policy number remains null while the PR is Pending Client Approval. It is generated when an administrator changes the status to pending_issuance.
  • Invoices and member breakdowns are generated when the status changes to pending_issuance.
  • Development stamp is always stored as 0 regardless of any value sent.
  • Status is always set to pending_client_approval (Pending Client Approval).
  • Broker defaults to the quotation broker; otherwise the authenticated broker is used.
  • Lead defaults to the quotation's main_lead unless lead_id is provided.
  • inception_date defaults to the quotation's resolved inception date when omitted, ensuring coverage dates are available for invoice generation.
  • The quotation premium is recalculated for the resolved inception date.

Note: To upload files, send the request as multipart/form-data. For JSON-only payloads, use application/json.

6.2 Get Purchase Request Status

GET /purchase-requests/{pr_number}/status/

Return the current status of a purchase request. {pr_number} can be either the KAF policy number (e.g., GTL20260000001) or the numeric PR ID.

Headers: Authorization: Bearer <access_token>

Success Response (200 OK):

{
  "id": 42,
  "kaf_policy_number": "GTL20260000001",
  "status": "pending_client_approval",
  "status_display": "Pending Client Approval",
  "quotation_id": 1089,
  "lead_id": 10,
  "inception_date": "2026-09-01",
  "created_at": "2026-09-02T10:00:00Z",
  "updated_at": "2026-09-02T12:00:00Z"
}

Rejected Response Fields: When status is rejected, the response also includes:

{
  "rejection_reason": "other",
  "rejection_reason_display": "Other",
  "rejection_reason_detail": "The client did not approve the final terms."
}

Note: The broker can only view purchase requests that belong to them or share their FRA ID.

6.3 Display Draft Contract PDF

GET /purchase-requests/{pr_number}/draft-contract/

Display the Draft Contract PDF generated for the Group Life purchase request. {pr_number} can be the KAF policy number or numeric PR ID.

Headers: Authorization: Bearer <access_token>

Response: A normal PDF response with Content-Type: application/pdf and Content-Disposition: inline, so browsers and API clients with PDF preview support display it directly instead of downloading it as an attachment.

Example:

GET /api/tailored-group-life/purchase-requests/GTL20260000001/draft-contract/
Authorization: Bearer <access_token>

Note: The PDF generated and stored by the existing Purchase Request Draft Contract service is returned. If it is missing, the endpoint generates and saves it first.

6.4 Display Invoice PDF

GET /purchase-requests/{pr_number}/invoice/

Display the initial invoice PDF associated with the purchase request. {pr_number} accepts either the KAF policy number or numeric PR ID.

Headers: Authorization: Bearer <access_token>

Response: application/pdf with Content-Disposition: inline. The selected invoice number is also returned in the X-Invoice-Number response header.

GET /api/tailored-group-life/purchase-requests/GTL20260000001/invoice/
Authorization: Bearer <access_token>

6.5 Download Member Breakdown Excel

GET /purchase-requests/{pr_number}/member-breakdown/

Download the member premium breakdown Excel stored on the initial invoice associated with the purchase request. {pr_number} accepts either the KAF policy number or numeric PR ID.

Headers: Authorization: Bearer <access_token>

Response: An .xlsx attachment. If the stored breakdown is missing, the existing invoice member-breakdown generator creates and saves it before returning it. The selected invoice number is returned in X-Invoice-Number.

GET /api/tailored-group-life/purchase-requests/42/member-breakdown/
Authorization: Bearer <access_token>

7. Endorsements

Endorsements are available after the Group Life policy is issued and active policy members have been created.

Note: All endorsement endpoints are only usable when the purchase request status is Issued.

7.1 Create Endorsement

POST /endorsements/

Create a draft endorsement using the issued Group Life Purchase Request ID.

Headers: Authorization: Bearer <access_token>

{
  "purchase_request_id": 1064
}

Response: 201 Created with the endorsement record and er_type: null. Use its id as {er_id} in the template, preview, and apply endpoints. The type is determined automatically as addition, update, deletion, or mixed after endorsement actions are imported or added.

7.2 Download Endorsement Excel

GET /endorsements/{er_id}/template/

Download the same bulk import Excel template generated by the admin Endorsement section. It contains example rows for Addition, Delete, and Update, plus dropdown lists for categories and subgroups, instructions, and an ActiveMembers reference sheet.

Headers: Authorization: Bearer <access_token>

Notes:

  • The Excel template contains three actions that can be performed on members: Addition, Delete, and Update.
  • Keep only the row for the action you want to perform and fill the data based on that action.
  • National ID is a mandatory field for all three actions.
  • For Update rows, only fill the fields you want to change; National ID is still required so the member can be matched.

Response: Excel attachment named ER-{er_id}-bulk-import-template.xlsx.

7.3 Preview Endorsement Excel

POST /endorsements/{er_id}/preview/

Dry-run parse of the completed bulk import workbook. The file is validated, a preview result is stored on the endorsement request, and the response shows the planned additions, deletions, updates, and any row-level errors or validation messages. Nothing is applied yet.

Headers: Authorization: Bearer <access_token>

Body: multipart/form-data with a file field named file. Do not manually set the multipart Content-Type; let the client generate its boundary.

Response: JSON preview summary including counts, per-row messages, and any errors.

7.4 Apply Endorsement Excel

POST /endorsements/{er_id}/apply/

Apply the last successful preview stored on the endorsement request. Creates endorsement items, updates the endorsement type, and executes the member changes immediately. Returns the number of items created, members affected, and the FRA sync result (if any).

Headers: Authorization: Bearer <access_token>

Response: JSON summary with items_created, members_executed, status, er_type, and fra_sync.

Error Responses:

  • 400 — No preview found, or the last preview contains errors

Workflow Summary

Typical broker journey for a Tailored Group Life quotation.

Login1.1 — obtain access_token
Create Lead2.2 — company info; optional parent lead
List Leads2.1 — get lead IDs for main_lead_id / parent
Create Quotation3.1 — product_type always group_life
Create Category3.2 — fixed ceiling or multiple of salary
List Benefits4.1 — choose benefit_ids for the plan
Download Template5.1 — Excel with salary column when applicable
Upload Members5.2 — replace scenario members and recalculate premium
Create PR6.1 — status pending client approval; policy number and invoice deferred until pending issuance

Status Flow

Purchase request lifecycle for Tailored Group Life.

StatusDescriptionEditable?
pending_client_approvalPending Client Approval (set automatically when the PR is created)Read-only for broker; documents can be added
pending_issuanceUnder operations review / pending issuanceNo
pending_reviewPending review by operationsNo
pending_signaturePending client signatureNo
issuedPolicy issuedTerminal
rejectedRejected by operationsTerminal

Note: Member uploads and category edits are only accepted while the quotation is still in a draft/priced state. Once a purchase request is created, the quotation is locked and the PR status is pending_client_approval.
